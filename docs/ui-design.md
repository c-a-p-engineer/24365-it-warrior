# UI/UXデザイン方針

## コンセプト

**スマホ監視端末 × 高速目視探索 × アニメーション**

## 固定原則

1. スマートフォン縦画面を優先する
2. ページ全体をスクロールさせない
3. 操作はログ行のタップのみ
4. 最初のプレイで説明文を読ませない
5. 重要情報は検索条件、ログ、正誤結果の順に強調する
6. 文字の可読性を演出より優先する
7. 色だけでなく `ERROR`、`WARN`、数値などの文字でも区別する

## 画面構成

- 上部：スコア、コンボ、残り時間
- 炎上度ゲージ
- 検索条件 `FIND`
- 中央：流れるログ端末
- 下部：エンジニアの表情、短いフィードバック、正解率

## ログ仕様

- 1行の高さは46px以上
- タップ領域は行全体
- 横スクロールなし
- 長い内容は省略する
- `ERROR`、`WARN`、`500`、`timeout`を文字色と太字で補助する
- 通常行のコントラストを下げ、検索対象を見つけやすくする

## 説明なしの導線

最初の正解行のみ以下を表示します。

- 水色の発光枠
- 指アイコン
- ゆっくりしたログ速度
- 正解後の `GOOD!`

以後は補助を削除し、通常プレイへ移行します。

## アニメーション

### 常時

- ログの縦移動
- ターミナル走査線
- タイトルの目線移動
- 炎上ゲージの揺らぎ

### 正解

- 行の拡大・分解・消滅
- 粒子
- 得点ポップ
- キャラクターリアクション
- コンボバナー

### 失敗

- 行の振動
- 全画面ノイズ
- 見落とし時の画面揺れ
- キャラクターのパニック

### 状態変化

- ターゲット切り替え
- 残り10秒のHUD警告
- HUMAN GREP MODEの画面オーラ
- ゲーム終了時のシャットダウン

## スマートフォン制約

- 最小対応幅：320px
- `100dvh`内へ収める
- セーフエリアを考慮する
- ピンチ、ドラッグ、文字入力を要求しない
- 誤タップを避けるため行間を詰めすぎない
- 低い画面では余白とパネル高さを縮小する

## アクセシビリティ

- `prefers-reduced-motion`で演出停止
- 正誤を色だけで表現しない
- 無音でも遊べる
- ボタンへフォーカスリングを表示する
