# UI/UXデザイン方針

## コンセプト

**暗い運用端末 × ポップなバグタイル**

短時間ゲームとして、説明を読まなくても「同じものを重ねる」「危険なものを消す」が伝わる画面を優先します。

## 基本原則

1. スマートフォン縦画面の1画面内に主要操作を収める
2. 盤面を最も大きく表示する
3. スワイプ操作を主、方向ボタンを補助とする
4. バグレベルを色・記号・名称の3要素で区別する
5. 本番安定度、得点、パッチ、連勤日数を常時表示する
6. アニメーションは操作結果の理解に使い、待ち時間を作らない

## ゲーム画面

上から次の順に配置します。

1. タイトル、連勤、得点、パッチ
2. 勤務先、エンジニア、本番安定度
3. 4×4盤面
4. パッチ適用とスワイプ説明
5. 方向ボタン

高さが低い端末では、説明パネルを省略して盤面と操作を維持します。

## バグタイル

| レベル | 色調 | 記号 |
|---:|---|---|
| 1 警告 | 青灰 | 警告記号 |
| 2 軽微 | シアン | バグ |
| 3 重大 | 黄・茶 | 爆発 |
| 4 緊急 | 橙・赤 | 炎 |
| 5 本番障害 | 濃赤 | ドクロ |

- タイル内にレベル名と必要パッチ数を表示
- レベル4以上は脈動アニメーションを付ける
- 新規タイルは拡大しながら出現
- パッチ適用中は除去可能タイルへ緑の内枠を表示

## 操作

### スマートフォン

- 盤面を上下左右へスワイプ
- パッチ適用ボタンをタップ
- 除去するタイルをタップ

### PC

- 矢印キー
- 方向ボタン
- パッチ適用後にタイルをクリック

## フィードバック

- マージ：`MERGE ×N`
- コンボ：画面上部へコンボ表示
- 本番障害生成：警告バナー
- パッチ成功：`FIX +得点`
- パッチ不足：赤い警告文字とタイル揺れ
- 無効なスワイプ：盤面全体を小さく揺らす

## アクセシビリティ

- 色だけで状態を区別しない
- 盤面タイルはボタン要素とし、読み上げ用ラベルを付ける
- 方向ボタンを常設し、スワイプ操作が難しい場合も遊べるようにする
- `prefers-reduced-motion`設定時はアニメーションを停止する
- 無音でも全情報を把握可能にする
