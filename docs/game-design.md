# ゲーム企画概要

## コンセプト

**24365 IT戦士**は、IT企業で発生する障害をカードで処理し、何日連続で勤務できるかを競うローグライト型カードゲームです。

IT業界のあるあるを、障害・カード・会社特性・職種効果としてゲームシステムに組み込みます。

## 基本ルール

1. 職種を選ぶ
2. 勤務先となる会社を選ぶ
3. その日に発生した障害をカードで解決する
4. 障害を解決すると翌日に進む
5. 7日ごとに週次イベントが発生する
6. 体力または信用が尽きるとゲームオーバー
7. 獲得した経験知で恒久要素を解放し、再挑戦する

## ハイスコア

主な記録は**連勤日数**です。

結果画面では、以下も表示します。

- 処理した障害数
- 累積残業時間
- 転職回数
- 増やした技術的負債
- 最終職種
- 最終勤務先
- ゲームオーバーの原因

## 職種

### エンジニア

障害へ直接ダメージを与える修正カードが得意です。

### PM

カードコストや障害の行動順を調整し、全体を管理します。

### QAエンジニア

テストや予防カードを使い、障害の発生や再発を抑えます。

将来的な候補：インフラエンジニア、SRE、情シス、営業、テックリード、CTO。

## 会社

### 大企業

- 体力や信用が高く安定している
- 会議、稟議、部署間調整が多い
- 直接的な障害は比較的少ない

### SES

- 初期性能や報酬が強い
- 配属先が定期的にランダム変更される
- 現場ごとにルールや有効カードが変わる

### 受託開発

- 報酬を獲得しやすい
- 仕様変更、納期、顧客対応の障害が多い
- 信用管理が重要になる

### 自社サービス

- カード強化や技術選定の自由度が高い
- 利用者増加により障害が強くなる
- 技術的負債が長期的に蓄積する

## カード分類

- **修正**：障害の耐久値を減らす
- **調査**：障害の特性や次の行動を確認する
- **防御**：体力・信用への被害を防ぐ
- **管理**：手札、コスト、行動順を操作する
- **危険対応**：強力だが技術的負債や再発を招く

## 障害分類

- アプリ障害
- インフラ障害
- 仕様障害
- 人的障害
- 顧客障害
- セキュリティ障害
- 経営障害
- AI障害

## 技術的負債

危険なカードを使うと、デッキへ邪魔カードが追加されます。

例：

- TODO
- コピペコード
- 謎のグローバル変数
- コメントアウト
- 誰も知らないバッチ

短期的な解決を選ぶほど、長期戦が難しくなる構造にします。
